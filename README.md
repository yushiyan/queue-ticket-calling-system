# 业务办理中心排队叫号系统

Windows 局域网取号与叫号服务。Node.js 22+、Express、WebSocket；无需数据库。

本项目由 **ChatGPT-Codex** 编写，依据实际业务需求开发与调整。

写这个纯闲的，买了个芯烨 XP-80C 打印机，只实机验证了这个打印机；

也可以指定其他打印机，但是未做测试。

仅供测试玩乐，因本程序造成的一切问题与作者无关。

## 系统要求

| 项目 | 要求 |
| --- | --- |
| 服务主机 | Windows 10 / 11，64 位；完整打印和语音功能依赖 Windows |
| 运行环境 | Node.js 22 或更高版本，及随附的 npm；开发验证版本为 Node.js 22.23.5 |
| 系统组件 | Windows PowerShell 5.1、CIM / WMI 打印机查询组件、Windows 打印后台处理服务 |
| 小票设备 | 已安装 Windows 驱动的 XP-80C，80mm 纸宽；其他打印机需自行验证纸张与驱动设置 |
| 语音设备 | 服务主机的扬声器或音箱，以及能朗读中文的 Windows SAPI 语音 |
| 客户端 | 支持 WebSocket、fetch、HTML dialog、AbortSignal.timeout 的现代浏览器，例如 Chrome / Edge 桌面版 |
| 取号屏 | 竖屏触控；已验证 1080×1920、720×1280 和 390×844 布局 |
| 网络 | 终端能访问服务主机的 TCP 3000 / 8000 端口，可通过环境变量调整 |
| 硬件参考 | 双核处理器、4GB 内存、至少 300MB 可用磁盘（不含 Node.js、系统及打印驱动）；此项为部署参考，未经负载基准测试 |

Node.js 和 npm 不随源码包分发。首次安装依赖需要能访问 npm 软件源；之后正常运行不依赖云端服务。SumatraPDF 可执行文件由 `pdf-to-printer` 依赖提供，保留其 `node_modules/pdf-to-printer/dist` 目录结构。此项目不安装驱动、不修改 Windows 默认打印机，也不修改防火墙规则。

## 从 GitHub 部署

1. 下载并解压源码，或克隆仓库。
2. 安装符合要求的 Node.js，进入项目目录执行 `npm ci`。
3. 在 Windows 中安装小票打印机驱动，确认音箱和中文语音可用。
4. 双击 `start.bat` 启动；也可执行 `npm start`。
5. 按下面的地址访问取号屏、窗口操作台或管理中心；局域网终端把 `localhost` 替换为服务主机 IP。

源码不包含 `data/`、已安装依赖、测试截图或本机打印机配置。首次启动自动生成默认数据和初始密码说明，没有额外的 OOBE / 初始化向导。默认队列为空、号码从 A001 开始、使用 Windows 默认打印机。修改密码和个性化设置都通过原有管理中心完成。

上传 GitHub 时提交源码、`LICENSE`、`package.json` 与 `package-lock.json`；不要上传运行时 `data/`、`node_modules/`、日志、临时小票和生成的压缩包。这些路径已加入 `.gitignore`。

## 启动与登录

已安装依赖时双击 `start.bat`。首次安装执行 `npm ci`；PATH 中 Node 可用时也可执行 `npm start`。启动脚本兼容 Windows PowerShell，并查找本机 Author Software nvm 已安装版本。

| 页面 | 地址 | 初始密码 |
| --- | --- | --- |
| 自助取号屏 | `http://服务器IP:8000` | 无需登录 |
| 窗口操作台 | `http://服务器IP:3000` | `000000`，登录时选择 1–99 号窗口 |
| 管理中心 | `http://服务器IP:3000/admin.html` | `000002`，无需窗口号 |
| 大厅展示屏 | `http://服务器IP:3000/display.html` | 无需登录；F11 可全屏 |

窗口与管理使用独立登录入口：普通页只接受窗口密码，点击下方“进入管理中心”后再输入管理密码。启动终端不显示初始密码，统一提示到 `data/initpass.txt` 查看，可在管理中心修改。浏览器刷新会恢复当前登录，登录有效期 12 小时；重启服务后重新登录。同一浏览器的标签页共用登录会话，管理员与办事员如需同时使用，请使用不同浏览器或独立浏览器配置。

直接覆盖升级时，只要保留已有 `data/`，窗口密码与排队数据就会保留。旧密钥文件及 `OPERATOR_KEY` 不再使用。管理员可修改两类密码；两类密码不可相同，修改会立即使对应类型的其他登录失效，当前管理会话保留。普通窗口不能修改共用密码，但可以在全部号码处理完毕后执行本轮清零。

## 权限与个性化

管理员统一设置：

- 中心名称、欢迎标语、大屏图标文字 / 上传 PNG、JPG、WebP / 关闭图标，以及三种大屏配色。图标最大 250KB。
- 大屏号码提示、叫号文案、底部通知、暂停通知、最近叫号条数，等候人数 / 已服务人数 / 日期时间 / 最近叫号区域开关。
- 号码前缀、数字最少位数、起始数字。须先结束所有排队与办理，再执行本轮清零，才能修改号码规则。老小票与历史记录保留发出时的号码。
- 取号页四种背景主题（青绿、蓝色、米色、紫色）、欢迎说明、按钮文字、成功提示、提示停留时间。页面专为竖屏触控布局，已验证 1080×1920、720×1280 和窄屏 390×844。
- 小票标题、号码提示、等待与时间文案、底部多行说明；模板输入框提供占位符说明和一键插入按钮。
- 语音开关、播报模板、是否读前缀与补零、重复次数、语速、音量、播报前提示音；支持主动点击试听。
- 等候容量，是否允许普通窗口暂停取号、是否允许指定等待号码叫号（默认均关闭）。
- 暂停 / 恢复取号、本轮清零、设置 JSON 导入导出、分类恢复默认、密码管理。
- 读取服务器已安装的打印机、选择小票打印机、发送不占用号码的测试凭条。打印机配置需先保存再测试。

保存后各页面自动更新。管理页面右侧为未保存文案预览；“查看已保存小票样式”和“试听已保存配置”使用已保存设置。试听在服务器音箱播放；查看小票样式只预览 HTML，不打印。导入与恢复默认只载入表单，检查后还需保存。导出包含已保存的个性化设置，不含密码和队列。多个管理员同时编辑时会检测版本冲突，避免覆盖他人设置。

普通窗口可叫下一位、重叫、完成、标记过号，以及在全部号码处理完毕后执行本轮清零（会再次确认）；管理员允许后可指定等待号码叫号、暂停 / 恢复取号。本机偏好包括号码放大、历史记录显示、仅查看本窗口记录，以及过号确认。偏好按窗口保存在当前浏览器，不影响其他设备、打印或大厅。

### 模板占位符

| 场景 | 支持占位符 |
| --- | --- |
| 小票文案 | `{center}` 中心名、`{number}` 完整号码、`{wait}` 前方人数、`{time}` 时间 |
| 大屏叫号、语音模板 | `{center}` 中心名、`{number}` 号码、`{window}` 窗口号 |

大屏及语音叫号文案必须包含 `{number}` 与 `{window}`。文案只按纯文本处理，不支持 HTML 或执行脚本。号码前缀最多 3 位字母、数字或汉字；位数为最少补零位数，编号超过位数后继续增长。语音默认只读实际数字，勾选“播报号码前缀和补零”后读完整号码。

## 小票打印

XP-80C 设置为 Windows 默认打印机，使用 80mm 小票纸。**保留原来的 CSS、80mm 纸宽、74mm 内容宽、字号、SumatraPDF 程序、临时文件及清理方式**。跟随默认打印机时仍执行原来的 `-print-to-default -silent -print-settings "noscale"` 命令；指定打印机时使用同一 SumatraPDF 的 `-print-to` 参数，并安全传入名称，其他参数不变。文案经转义后填入原 HTML。默认文案与原版一致。长文案会自动换行，实际纸张效果需现场确认。

管理中心“打印机与测试”可以刷新列表、选择目标并保存。列表来自服务器电脑，不是浏览器所在电脑；默认跟随 Windows 默认打印机。测试打印使用“测试凭条”样例，不发号、不加入队列、不语音播报；只反馈任务发送结果，实际出纸仍需现场确认。

打印失败记录在服务终端；页面取号成功代表号码已登记，不代表纸张实际打印成功。原方案共用 `ticket.html`，并发取号时的文件竞争仍未调整；修改打印方案需先讨论。

## 数据与业务

取号后进入共享先进先出队列；窗口须先完成或标记过号，再叫下一位。指定叫号只允许选中尚在等待的号码，不会凭空创建号码。暂停仅停止新取号，已有号码继续办理。

本轮清零只在队列为空且所有窗口结束办理时允许执行，不自动按日期清零。统计自上次清零开始计算，历史最多保存 500 条。最近 1000 个取号请求支持幂等重试，网页请求结果不明时不要清除会话存储。

| 文件 | 内容 |
| --- | --- |
| `data/queue.json` | 队列、窗口状态、统计、操作记录、发出时的号码 |
| `data/config.json` | 首次保存后生成的个性化设置及版本 |
| `data/settings.json` | 窗口共用密码的加盐哈希 |
| `data/admin-password.json` | 管理员密码的加盐哈希 |
| `data/initpass.txt` | 初始密码说明，非当前密码备份，不通过网页提供 |

每次变更先写临时文件再替换，保存失败不确认操作。重启恢复数据，数据损坏时停止启动。请定期停服备份整个 `data` 文件夹；设置导出不能代替数据备份。只允许一个服务实例使用同一数据目录。

默认监听所有网卡，供受信任局域网使用。采用角色校验、窗口绑定、HttpOnly/SameSite 会话、跨站检查和限流；HTTP 不加密，不直接暴露公网。公共状态接口包含排队号码与公开个性化配置，不应填写个人资料或秘密。需要跨网访问时先配置 VPN 或适配 HTTPS 代理。

环境变量：`KIOSK_PORT`（8000）、`WINDOW_PORT`（3000）、`KIOSK_HOST`、`WINDOW_HOST`（默认均为 `0.0.0.0`）。HTTPS 反向代理须适配 WebSocket Origin 检查后部署。

## 验证

`npm test`：验证队列恢复、存储失败、幂等请求、角色权限、窗口绑定、密码修改、配置校验与持久化、指定叫号、历史号码保留、小票转义，默认打印 CSS 与命令兼容、打印机选择、模拟测试打印、独立登录入口与普通窗口清零。测试使用临时目录和模拟打印 / 语音，不触发硬件。

`node tests/preview.js`：启动隔离样例服务，窗口端 `3100`、取号端 `8100`。只用临时数据，打印与语音均为模拟，不修改实际服务队列。

### 打印机列表兼容性

打印机列表使用 PowerShell / CIM 输出 JSON，保留中文、带冒号与网络共享名称，不再解析 PowerShell 的格式化文本。列表来自运行服务的 Windows 账号。此逻辑与实际小票打印命令分离。

可用 `node scripts/check-printer.js` 只读检查列表；加 `--print` 会通过隔离的管理接口发送一张真实测试凭条，加 `--printer=XP-80C` 可测试指定打印机。诊断不会修改实际队列与配置，需人工确认实际出纸。
